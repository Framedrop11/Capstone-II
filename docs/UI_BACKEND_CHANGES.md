## Contract facts verified at U0

- The active contract is `services/core-api/openapi/openapi.yaml` (OpenAPI 3.1); the prompt's shorthand path does not exist.
- Existing operations cover auth login/callback/refresh/logout; patient questionnaire submit, predictions, report, consents, audit; doctor shared patients, scoped report token/read, outcome; admin users/roles, audit and model versions; and health/readiness/metrics.
- `GET /api/v1/admin/model-versions` supports the admin model list; patient/doctor worklist, notification, and system status needs cannot be inferred from it.
- Current contract responses are loosely typed in several places (`Page.items`, consent, notification-free worklist); U2 client generation can expose the exact declared shape, but backend schema strengthening may be needed before implementation.
